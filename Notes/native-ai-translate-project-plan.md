# 原生 AI 翻译客户端：项目规划草案 v0.1

日期：2026-10-07。定位：自用优先、开源、非营利的 Apple 平台翻译工具。以下采用单人维护、macOS 先形成日常使用闭环、随后完善 iOS / iPadOS、最后交付 visionOS 的假设；语言优先级由实际使用样本决定。

## 1. 产品定义

一句话：像系统翻译一样随手可用，同时能够借助用户选择的生成式模型理解语境、处理截图，并解释关键措辞。

核心任务：我在阅读或写作时，想把文字或图片变成可信、自然、可以直接使用的译文，同时决定内容是否离开设备。

产品不是聊天入口。主界面应始终围绕原文、译文、语言和复制。解释、补充语境、改变表达是围绕同一次翻译展开的后续操作。

五项原则：

1. 先忠实，再自然；生成式模型不应随意增补信息。
2. 用户能看见本次使用哪个模型，以及内容在哪里处理。
3. 快速获得第一版译文；解释和润色按需请求。
4. 同一翻译任务可切换引擎，各平台使用适合自己的界面。
5. 对个人维护者而言，可维护性比支持所有服务商和模型更重要。

成功不看下载量，而看自己是否每天愿意用、是否减少复制粘贴和切换应用、复杂语境是否比系统翻译更好。

## 2. 当前技术依据与边界

Apple 在 WWDC26 公布了 Foundation Models 的新 LanguageModel 抽象、第三方模型接入、本地 MLX / CoreAI 接入、图片输入和 Private Cloud Compute。相关新 API 应按具体 SDK 与运行系统检查可用性，不能把 WWDC 宣布直接视为所有目标设备已经支持。

建议采用两条明确路径：

- 26 系统基线：已有系统模型能力 + 自己的云端适配 + 本地 OCR。
- 27 能力增强：在可用时采用新的统一 LanguageModel 接口、系统模型图片输入和 MLXFoundationModels 桥接。

如果开发者自己的所有设备都使用 27，可在开始实现前主动提升最低版本，以降低维护成本；这应是明确决策，而不是框架选择带来的隐性后果。

Apple 系统模型由系统提供和管理，不属于应用里的可自由下载、替换的模型库。使用前检查硬件资格、Apple Intelligence 状态、模型准备状态及语言支持。

Gemma 4 已有官方模型卡，包含适合端侧试验的 E2B / E4B 版本。MLX Swift LM 已提供 Gemma 4 相关实现和 Foundation Models 桥接；桥接文档要求 27 SDK。架构支持、文本能力、图片能力与特定量化权重能否在具体设备运行，仍需分别验证。

MLXFoundationModels 不是应用必须依赖的领域接口。对旧系统可使用 MLX 的直接接口，对新系统可使用其 Foundation Models 桥接。核心翻译逻辑无需因此变化。

默认翻译应用：Apple 提供 TranslationUIProvider 路径，可针对 iOS / iPadOS 进行验证。它值得早期技术探针；不应预设它适用于每个平台或接管所有第三方应用的翻译行为。

Private Cloud Compute 可作为后续候选，但属于云端推理；不能在隐私 UI 中归入“本机模型”，也不应把资格或免费额度当作项目成立的前提。

## 3. 范围与版本

### v0.1：自用 macOS MVP

- 文字输入、粘贴，源语言自动检测及手动覆盖，选择目标语言。
- 一个正式支持的 BYOK 云端适配器，Apple 系统模型作为可用时的本机选项。
- 图片拖入、粘贴和文件导入；本地 OCR；识别文字可编辑。
- 流式译文、取消、重试、复制。
- 补充语境；按需解释关键措辞。
- 原文与译文并排，键盘完成主要流程。
- 模型设置、连接测试、Keychain 存储密钥。
- 本地历史记录，可关闭；原图默认临时处理。

定义完成：开发者连续一周日常使用；取消和出错不丢输入；常见图片可通过 OCR 翻译；本机模式不会发起推理网络请求。

### v0.2：系统入口与移动使用

- macOS 菜单栏入口、用户主动粘贴、可选自定义快捷键。
- iOS / iPadOS 的系统分享入口和照片选择；相机扫描只在支持的设备启用。
- iOS / iPadOS 默认翻译扩展：探针验证成功后交付。
- iPhone 上下布局；iPad 分栏和拖放；宽度变化时布局自适应。
- 无障碍、动态字体、VoiceOver、简体中文及英文 UI。
- 一组真实语料的质量回归评估。

### v0.3：下载模型

- 先在 Mac 支持一个实际验证过的 Gemma 4 小模型、一个量化版本。
- 下载、暂停或重试、校验、加载、卸载、删除。
- 展示模型来源、版本、下载体积、许可证、实测兼容设备。
- 限制上下文和并发；取消后释放工作；内存不足能恢复。
- iPhone / iPad 实机测量后逐机型启用，visionOS 另行验证。
- 用户自己的本机推理服务可作为过渡，但不等同于应用内下载推理。

### v1.0：四平台可靠体验

- visionOS 首先提供标准 SwiftUI 窗口，支持文字及导入图片。
- 强化截图选区、图片原文和译文的区域对应。
- 完成发布说明、安装指南、贡献指南和兼容矩阵。

首版不做：实时语音对话、视频翻译、网页全文替换、PDF 排版回填、AR 文字覆盖、多模型自动竞技、账户和服务器、iCloud 同步、自动读取其他应用内容。

## 4. 信息架构与 UI

顶层仅保留三个区域：翻译、历史、设置。

### 翻译

语言栏：自动检测 / 手动源语言 → 目标语言；只有明确源语言时才提供可靠的交换语种动作。

原文区：TextEditor，粘贴和图片入口；图片识别后保留缩略图和可编辑 OCR 文字。简单截图直接继续，识别低置信度或多栏复杂内容时提供检查和选区。

译文区：先展示正文。底部依次为复制、解释、补充语境、表达调整。解释默认折叠；“更自然”和“更忠实”保留版本，不覆盖原文。

执行栏：当前模型、翻译 / 停止、简短处理位置说明。用户不需要进入设置才能知道“本机”还是“云端”。

图片默认路线为“本地识别，仅将识别文字交给模型”。如果选择直接图片理解，显示“将发送所选图片区域”，并由用户主动执行。不能因为 OCR 失败自动把原图上传。

### 历史

原文、译文、语言对、模型和时间；搜索可后置。历史默认为本机文字记录，可关闭、单条删除、全部删除。原始图片默认不长期保存。后续设置中可单独允许保存图片。

不将旧翻译自动拼进新请求。历史记录不是跨任务模型记忆。

### 设置

- 模型：Apple 本机模型、云端服务、下载模型，分组而非混为一张榜单。
- 云端服务：提供商、Endpoint / Model ID（高级项）、密钥、测试连接。
- 下载模型：可用空间、来源、大小、设备要求、下载或删除；只列维护者确认支持的组合。
- 偏好：默认目标语言、翻译模式、键盘快捷键、历史开关。
- 隐私：数据发送位置、历史和图片保存、可导出的脱敏诊断。

首次启动：系统模型可用时直接进入翻译；不可用时展示“连接云端服务”与“查看本机模型选项”。不先强制下载数 GB 文件。下载模型入口在正式支持该平台后出现。

### 平台适配

| 平台 | 主布局 | 高频入口 | 原生体验重点 |
|---|---|---|---|
| macOS | 可折叠历史侧栏 + 原文译文分栏 | 主窗口、菜单栏、用户主动粘贴、拖放 | 命令菜单、焦点、键盘、窗口尺寸 |
| iOS | 原文在上、译文在下，设置与语境为 sheet | App、分享、默认翻译扩展、照片 | 单手操作、键盘避让、动态字体 |
| iPadOS | 宽窗口分栏，窄窗口上下排列 | 分享、拖放、照片 | 外接键盘、分屏、窗口变化 |
| visionOS | 标准二维窗口，原文和译文舒适排布 | 文本、导入图片 | 视线目标、系统控件、舒适阅读 |

共享的是任务状态和可组合的局部组件。分享扩展、菜单栏、相机和窗口管理是独立平台入口；不能以大量条件编译把所有行为塞入一个根视图。

## 5. User story map

主干：进入工具 → 提供内容 → 决定语言和处理方式 → 获得译文 → 调整理解与表达 → 使用和保留结果。

| 发布切片 | 进入 | 提供内容 | 选择处理 | 获得译文 | 调整结果 | 使用与保留 |
|---|---|---|---|---|---|---|
| v0.1 自用闭环 | Mac 主窗口 | 粘贴文字、图片导入、OCR 校对 | 自动识别、目标语言、BYOK / Apple 本机 | 流式、停止、重试 | 补充语境、解释措辞 | 复制、本地历史、删除 |
| v0.2 系统入口 | 菜单栏、分享、默认翻译扩展 | iPhone 照片、iPad 拖放、选区 | 记住语言偏好，明确数据去向 | 小屏适配、扩展轻量请求 | 更忠实 / 更自然，版本保留 | 返回原 App，按入口能力分享或替换 |
| v0.3 本地模型 | 保留已有入口 | 本地 OCR | 下载模型、兼容与加载状态 | 离线推理、内存不足恢复 | 经评测的固定翻译配置 | 模型管理、可控缓存 |
| v1.0 四平台 | visionOS 窗口 | 文字与导入图片 | 平台能力一致描述 | 实机性能与无障碍达标 | 图片区域对应 | 开源发布、文档 |

### 三个关键故事与验收

**阅读文字**：作为用户，我希望粘贴一段陌生语言后得到自然且忠实的译文。

验收：记住目标语言；流式输出不跳动；修改原文不会让上一任务的迟到输出覆盖结果；翻译时仍可停止；一键复制当前版本。

**翻译图片**：作为用户，我希望看懂截图中的文字，而不必先手动抄写。

验收：先进行本地识别；可以修改 OCR；无文字时提示重新选区；默认不上传原图；复杂布局不擅自重新排版或补全缺失内容。

**理解语境**：作为用户，我希望处理惯用语、邮件语气、术语和歧义。

验收：默认只有译文；需要时解释具体词句；补充语境产生新版本；人名、数字、网址、否定和条件关系受保护；有歧义时可提供备选表达，不伪装成确定答案。

## 6. 框架定义

建议：SwiftUI + Observation + Swift Concurrency，轻量 MVVM，核心逻辑做成 Swift Package。首版避免大型状态管理框架和多层架构空壳。

依赖方向：

```text
Apple 平台入口 / SwiftUI
          ↓
TranslationWorkspace（界面状态）
          ↓
TranslationCoordinator（单次任务编排）
          ↓
TranslationCore（请求、模式、提示、结果、规则）
          ↓ 使用协议
ModelProvider / TextRecognizer / Repositories
          ↑ 实现
AppleFM / CloudAPI / MLX / Vision / SwiftData / Keychain
```

核心模块：

| 模块 | 职责 |
|---|---|
| TranslationCore | 与 UI、平台、供应商无关的任务和翻译规则 |
| TranslationWorkspace | 原文、目标语言、选择的模型、状态、版本；MainActor 更新 UI |
| TranslationCoordinator | 输入快照、OCR、分块、模型选择、取消、结果校验 |
| ModelProviders | 云端和本机适配；能力、可用性和统一错误 |
| ImagePipeline | 导入、方向、缩放、裁剪、OCR 和区域对应 |
| Persistence | 文本历史、偏好、密钥、模型文件索引 |
| PlatformIntegrations | 菜单栏、分享、默认翻译、App Intents、平台权限 |

ModelProviders 与 ImagePipeline 是独立实现模块，不相互嵌套。UI 不处理 HTTP、下载器或模型对象。

优先定义以下类型：

- TranslationRequest：不可变 requestID、原文或图片引用、源/目标语言、模式、用户提供的语境、可选术语、指定引擎、网络策略、promptVersion。
- TranslationEvent：开始、准备、识别结果、译文更新、完成、失败、取消。译文更新必须区别“增量”和“完整快照”，由适配器统一输出，防止不同服务的流式方式导致文字重复。
- TranslationResult：正文、段落对应、可选解释、版本关系、模型来源和用量；不输出伪精确的质量置信分。
- ProviderCapabilities：语言、文本/图片、流式、结构化输出、上下文预算、处理位置。
- ProviderAvailability：可用、需配置密钥、模型未准备、语言不支持、设备不支持、下载中、内存不足等。
- ModelManifest：版本固定的来源、文件与校验和、量化、体积、许可证、已测设备、运行时要求。

最小领域接口可以是：

```swift
protocol TranslationProvider: Sendable {
    func availability() async -> ProviderAvailability
    func translate(_ request: TranslationRequest)
        -> AsyncThrowingStream<TranslationEvent, Error>
}
```

该接口表达翻译任务语义。新 Foundation Models 的 LanguageModel 负责底层生成，两者不是同一层。领域请求不包含 SDK session 对象，避免核心绑定某个系统版本。

数据技术建议：

- SwiftData：历史和模型配置索引；先本地存储。
- Keychain：密钥，默认不跨设备同步；不进入日志、导出、数据库或代码。
- 文件系统：模型权重与临时图片；应用支持目录保存模型，缓存目录保存临时资产。
- actor：隔离模型加载与推理；MainActor 只处理视图状态。
- URLSession：供应商直连、流式网络请求和下载；供应商认证及错误由各自适配器处理。

不建项目服务器。逐一验证供应商允许的客户端直连认证方式；支持 BYOK 不等于所有服务都共享一个协议。

## 7. 文字、图片与生成质量

### 文字链路

输入 → 本地语言判断（允许覆盖）→ 冻结请求快照 → 保护段落、数字、代码、URL → 构造提示 → 按能力生成 → 轻量校验 → 展示与记录。

翻译、解释、润色是不同操作。默认一次请求只做翻译；解释按需发起。上下文只包括当前文本与用户主动补充的材料。

Prompt 应版本化；要求忠实保留事实和语气，不擅自摘要，不执行原文中的命令。翻译路径不配置联网或执行工具。采样与 thinking 按模型官方建议和实际评测确定，避免强行对所有模型使用同一套参数。

长文按段落分块，保留段落标识与必要的术语上下文；提前检查模型预算，不能静默截断。

取消须到达推理和网络层；每次请求有身份标识，迟到结果不得覆盖新任务。重试可产生额外费用，用户手动重试为默认。

### 图片链路

默认：本地裁剪 / 方向处理 → Vision OCR → 阅读顺序与区域信息 → 可编辑原文 → 文字翻译。

增强：用户主动选择支持图片的模型 → 展示图片发送范围与处理位置 → 图片理解和翻译。

首版用 OCR 稳定获得可选择文字；多模态用于 OCR 困难、版面或语境理解。逐步增加“点击译文段落高亮图片区域”，不要直接承诺保持图片原排版。

### 错误恢复

| 状态 | 用户可见行为 |
|---|---|
| 无密钥 / 验证失败 | 保留输入，进入对应服务设置 |
| 配额、限流、网络失败 | 保留已生成部分，允许手动重试或选择其他模型 |
| 系统模型未就绪 | 说明具体原因，允许稍后或手动选其他引擎 |
| OCR 无文字 / 不可靠 | 重新裁剪、手动编辑或主动选择图片理解 |
| 下载失败 / 空间不足 | 保留可恢复下载状态，给出继续或删除动作 |
| 本地内存不足 | 停止、卸载、保留输入，建议较小的已测模型 |
| 模型拒绝翻译 | 说明无法处理，允许手动切换；不静默改写或删除原文 |

禁止静默从本地切到云端。翻译处理位置的变化必须是用户主动选择，或用户事先明确授权的可见策略。

## 8. 扩展与模型管理约束

分享和默认翻译扩展使用独立的轻量 target。通过合适的共享容器与密钥访问配置读配置，但不直接继承主应用的整个数据库和推理进程。

扩展不是长期驻留推理场所。默认只执行适合其生命周期的轻量路径；大图片和较大的下载模型转交主应用。Apple 系统模型能否在对应扩展稳定执行，纳入探针验收，不先承诺。

本地模型目录采取“维护者验证过的清单”，首版不开放任意远程代码或模型执行入口。下载固定 revision，校验文件哈希；支持兼容标记、损坏恢复和删除。

不要以参数名估算可用性：下载文件、权重、KV cache、图像处理、运行缓冲都会影响峰值内存。文档发布实测，而不是把“E2B”翻译成“只需要 2GB”。

## 9. 质量与验收

在开发前建立 50–100 条来自自己使用场景、经过脱敏或重写的文字样本，以及约 20–30 张测试图片。语言对由个人需求决定，例如中英，可额外加入实际需要的其他语言。

文字覆盖：日常句子、邮件、惯用语、讽刺、专业术语、歧义、否定、数字单位、人名、混合语言、多段落和代码。

图片覆盖：截图、菜单、斜拍、低分辨率、多栏、混合语言、无文字；先评估 OCR，再评估翻译，避免混淆失败来源。

对照系统翻译及候选引擎，盲评忠实、自然、格式、术语、遗漏与增补。记录模型版本、提示版本、首段延迟、总耗时、用量、峰值内存及失败率；模型自评仅作辅助。

建议初始发布门槛（项目目标，并非平台性能保证）：

- 选定测试设备与语言对下，普通短句中位首段延迟争取小于 2 秒，整段争取小于 5 秒；冷启动和热启动分开报告。
- 关键数字、否定与条件关系在指定发布集无严重错误。
- 在自己的困难样本中，盲评更偏好项目译文的比例达到约 70%，同时披露样本和局限。
- 取消、切换、断网、权限拒绝和内存不足均不丢输入。
- 本机推理模式不发送待翻译内容；首次下载网络活动独立标记。
- 主要流程通过 VoiceOver、键盘、动态字体和窗口宽度检查。

必要测试：请求取消与迟到事件、段落映射、供应商响应解析、密钥不写日志、模型 manifest 和文件校验、代表性 UI 流程。生成质量做评估集，不用固定输出字符串的单元测试代替。

## 10. 推进计划

估算按全职等效工作日，仅用于排序；个人业余开发应按可投入时间换算。不要承诺一个统一“四平台全部做完”日期。

| 阶段 | 工作量参考 | 交付与退出条件 |
|---|---|---|
| A 技术与质量探针 | 3–5 天 | 同一组样本跑通 Apple 本机、一个 BYOK 云端、Vision OCR；测试默认翻译扩展和一个 Gemma 小模型可行性；选基线 |
| B macOS 文字闭环 | 5–8 天 | SwiftUI 编辑器、流式、停止、复制、设置、Keychain；每天可用 |
| C 图片与语境 | 4–7 天 | OCR 校对、图片导入、语境、解释、历史；形成 v0.1 |
| D 系统与移动入口 | 6–10 天 | 菜单栏、分享、默认翻译路径、iOS/iPadOS 适配；形成 v0.2 |
| E 下载模型 | 5–10 天 | 只交付一个验证过的模型组合；性能和异常恢复达标 |
| F visionOS 与公开发布 | 4–7 天 | 实机验证、文档、可复现构建、兼容说明 |

A 阶段只验证本地模型和扩展，不实现完整下载中心。最重要的里程碑是 v0.1 连续使用一周，收集真实问题后再扩大范围。

## 11. 开源与维护

代码许可证可先选择 MIT，便于自用工具和社区复用。模型权重及依赖按各自许可证处理，代码许可证不覆盖所有资产。

公开仓库包含 README、ROADMAP、CONTRIBUTING、SECURITY、架构说明、脱敏评测样本、供应商兼容矩阵、系统 / 设备矩阵。示例配置只提供占位值。

项目不提供公共 API Key、统一代理、推理配额或托管账户。UI 明确“客户端免费；第三方模型服务费用由用户自己的账户承担”。

先发布源码与安装说明，再视维护成本发布签名构建及商店版本。非营利不意味着分发、签名和维护没有支出；不要把商店上架列为自用 MVP 的必需条件。

接受贡献的边界：可测试的供应商适配、语言 UI、真实设备报告、翻译评测、无障碍修复。新模型必须附版本、兼容设备和验证结果，避免仅因热度进入支持清单。

## 12. 下一步决策

开始编码前确认四项即可：

1. 首先解决哪台设备上的日常任务。
2. 最重要的两个语言方向。
3. 首个已有 Key 的云端提供商。
4. 最低系统版本采用 26 兼容基线还是 27 简化基线。

建议第一项工程任务不是搭建模型商城，而是“同一组 50 条文本和 20 张截图，在现有系统翻译、Apple 本机模型和一个 BYOK 云端模型之间做对比”，据此决定默认引擎与 v0.1 范围。
